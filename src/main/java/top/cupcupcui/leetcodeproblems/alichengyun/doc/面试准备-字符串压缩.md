## 题目要点背诵

### 核心规则（必须记住）
1. **压缩规则**：利用字符重复次数
   - 统计连续相同字符的数量
   - 格式：字符 + 出现次数
   - 示例：`"aabcccccaaa"` → `"a2b1c5a3"`

2. **返回条件**：
   - 压缩后字符串**没有变短** → **返回原字符串**
   - 压缩后字符串**更短** → **返回压缩后的字符串**
   - 示例2：`"abbccd"` → `"a1b2c2d1"`（变长了）→ 返回`"abbccd"`

3. **字符范围**：
   - 只包含大小写英文字母（a-z, A-Z）
   - 不用考虑其他字符
   - 长度范围：[0, 50000]

### 示例对比（必须理解）

**示例1:** `"aabcccccaaa"` → `"a2b1c5a3"`
```
字符分组：aa | b | ccccc | aaa
按组计数：a×2 | b×1 | c×5 | a×3
压缩结果：a2b1c5a3
比较长度：原串11，压缩后8 → 返回a2b1c5a3
```

**示例2:** `"abbccd"` → `"abbccd"`
```
字符分组：a | bb | cc | d
按组计数：a×1 | b×2 | c×2 | d×1
压缩结果：a1b2c2d1
比较长度：原串6，压缩后8 → 返回abbccd（不变）
```

**边界示例:** `"abcd"` → `"abcd"`
```
字符分组：a | b | c | d（每个字符只出现1次）
压缩结果：a1b1c1d1
比较长度：原串4，压缩后8 → 返回原串
```

## 暴力求解法（背诵版）

### 记忆口诀：
**"遍历字符逐个比，相同就计数，不同就拼接，最后比长度"**

### 具体步骤（按顺序记忆）：

#### 第一步：边界检查
```java
// 字符串长度为0或1，直接返回（不需要压缩）
if(s == null || s.length() <= 1) {
    return s;
}
```

#### 第二步：初始化变量
```java
StringBuilder compressed = new StringBuilder();  // 存储压缩结果
char currentChar = s.charAt(0);  // 当前字符
int count = 1;  // 当前字符连续出现的次数（初始为1）
```

#### 第三步：遍历字符串（从第2个字符开始）
```java
for(int i = 1; i < s.length(); i++) {
    char c = s.charAt(i);

    // 如果字符相同，计数加1
    if(c == currentChar) {
        count++;
    } else {
        // 字符不同，先处理当前字符
        compressed.append(currentChar).append(count);

        // 更新当前字符和计数
        currentChar = c;
        count = 1;
    }
}

// 循环结束后，处理最后一个字符组
compressed.append(currentChar).append(count);
```

#### 第四步：比较长度，返回结果
```java
String result = compressed.toString();

// 如果压缩后不比原串短，返回原串
if(result.length() >= s.length()) {
    return s;
}

// 否则返回压缩串
return result;
```

## 面试时快速记忆要点

### 核心算法逻辑（三句话）：
1. **遍历统计**：从头到尾，记录当前字符和计数
2. **分组处理**：字符变化时，把字符+计数拼接到结果
3. **比较返回**：最后比长度，谁短返回谁

### 时间复杂度：O(n)
- 只遍历字符串一次
- StringBuilder拼接是O(n)总时间

### 空间复杂度：O(n)
- StringBuilder需要额外空间存储结果
- 长度不超过2n（最坏情况每个字符1次）

> 这个算法的时间复杂度是O(n)，因为我们只遍历一次字符串；空间复杂度也是O(n)，用于存储压缩结果。使用了StringBuilder来提高拼接效率。"

## 关键逻辑说明（必须理解）

### 为什么用StringBuilder？
```java
// 避免字符串拼接的低效率
// s += "a"; 每次都是O(n)（创建新字符串）
// StringBuilder.append() 平均O(1)
```

### 为什么count初始化为1？
```java
// 因为第一个字符已经出现了1次
// 例如："aab..."
// currentChar='a'，count=1（第一个a）
// 第二个a，count++ → 2
// 第三个不同字符，结束这一组
```

### 为什么循环结束后还要append一次？
```java
// 因为最后一组字符没有触发"下一个字符不同"的判断
// 例如："aab"（没有第四个字符触发b的处理）
// 循环中处理了'a'组，结束时currentChar='b'，count=1
// 需要手动处理最后一组
```

## 代码模板（面试时先写框架）

```java
public String compress(String s) {
    // 1. 边界检查
    if(s == null || s.length() <= 1) {
        return s;
    }

    // 2. 初始化
    StringBuilder compressed = new StringBuilder();
    char current = s.charAt(0);
    int count = 1;

    // 3. 遍历（从第二个字符开始）
    for(int i = 1; i < s.length(); i++) {
        char c = s.charAt(i);

        if(c == current) {
            count++;
        } else {
            compressed.append(current).append(count);
            current = c;
            count = 1;
        }
    }

    // 4. 处理最后一组
    compressed.append(current).append(count);

    // 5. 比较长度并返回
    String result = compressed.toString();
    return result.length() < s.length() ? result : s;
}
```

## 与其他算法的关系（加分项）

这类问题属于**游程编码（Run-Length Encoding, RLE）**：
- 无损压缩算法的一种
- 适用于连续重复数据的压缩
- **变体**：如果超过3次重复才压缩（因为2次不划算）

**相关算法：**
- 哈夫曼编码（频率统计）
- LZW压缩（字典压缩）
- 行程编码（与本题类似）

可以说："这个算法是游程编码的一种实现，适用于压缩连续重复字符。"

## 优化和变体（如果面试官问）

### 变体1：只在节省空间时才压缩
```java
// 可以设置一个阈值：count >= 3才压缩

if(count >= 3) {
    compressed.append(current).append(count);
} else {
    // 重复count次字符
    for(int i = 0; i < count; i++) compressed.append(current);
}
```
